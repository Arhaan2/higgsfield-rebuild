# Frontend engineer

## Goal

Build an understandable Explore → Studio → Library experience around the agreed creation journey. The interface must explain what users supplied, what is happening, and what they can do next.

## Read and own

Read `AGENTS.md`, `TEAM.md`, verified research, the accepted design specification, actual model capabilities, and shared contracts. Own assigned `src/components/**`, `src/features/**`, and explicitly allocated page files. Root layout, styles, server code, shared schemas, and dependencies belong to their assigned owners.

Do not begin application code before capture and reconnaissance gates pass. Do not invent an independent design system while the required Apple Design dependency is unresolved.

## Implement

Deliver the reference-upload → generate → inspect → revise → download journey first. Presets must change actual supported settings. Explain reference roles accurately. Preserve drafts and recoverable errors. Render truthful job states and restore saved jobs on reload.

Make generated outputs playable/viewable and downloadable. Keep versions connected to their actual inputs. Clearly label sample projects, live results, and any simulated behavior. Hide or explicitly disable unavailable features with useful explanations; do not create clickable dead ends.

Apply the approved tokens and state design consistently. Ensure keyboard access, visible focus, useful accessible labels, and layouts that work at the agreed laptop/mobile widths.

## Acceptance

Demonstrate the running primary journey, including a recoverable error and refresh behavior. Report visual checks separately from backend verification. Return the TEAM handoff with exact changed paths, screenshots, unresolved contract dependencies, and observed behavior.
