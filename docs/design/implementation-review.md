- **Source:** `components/studio/StudioView.tsx:77` renders the image action unconditionally for an image; `:43` supplies `PRESETS[1].draft.prompt` even when this image is already the current reference. `src/client/use-studio.ts:247–252` saves the current state, replaces the active operation's draft, then saves again. The notice at `:251` describes the original *asset* and prompt staying unchanged; an uploaded image has no recorded generation prompt. `components/studio/AssetDetails.tsx:34` exposes the same action for uploaded/generated images.
- **Reproduction for root:** open a saved motion draft with its uploaded reference selected, write a distinctive movement prompt, save, then activate Animate this image under that same reference. Inspect prompt, project identity and resulting notice. No generation is needed. This exact activation sequence was not run by this reviewer.

The current visible action suggests advancing the animation task; code replaces the text with a preset and saves it in the current shot. This is a concrete risk to entered work, not a claim that a provider call occurs.
- **Smallest proposed repair:** when the inspected image already equals the active motion start frame, make the action focus the existing movement field without changing/saving its draft; label this branch **Edit movement**. For a different image, use **Use as start frame** with a concise draft-only explanation, and retain the current motion text where compatible. Root/frontend should decide the exact bounded behavior before editing; keep API, immutable job snapshots, generation guards and sample provenance intact. Do not add a confirmation dialog as the first solution.
- **Acceptance:** repeat with a distinctive saved and unsaved prompt; same-reference action preserves both and moves focus usefully. A different-reference action truthfully identifies its draft effect; prior saved jobs/assets remain unchanged. Render desktop/phone and verify actual keyboard behavior. This follows Apple Design §16 agency, direct labels and control/content mapping, and RECON's task-label alignment/iteration continuity findings. The accepted D2 action wording was a proposal; these rendered circumstances expose a specific ambiguity worth correcting.
